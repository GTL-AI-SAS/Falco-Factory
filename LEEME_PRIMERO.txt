FALCO FACTORY STUDIO v1.6.3

1. Extrae el ZIP completo en una carpeta nueva.
2. En Windows abre ABRIR_FALCO_STUDIO.cmd. Requiere Node.js 22.12.0 o superior. La primera apertura instala las dependencias con el lockfile de Wrangler 4.166.0 incluido.
   Se crea ABRIR_FALCO_STUDIO.lnk en esta misma carpeta con el icono oficial de FALCO. Usa ese acceso directo para abrir Studio. Si mueves la carpeta, abre el .cmd una vez para actualizarlo.
3. En PowerShell, desde esta carpeta, ejecuta npm.cmd run falco:auth:secure para usar Wrangler OAuth con Windows Credential Manager.
4. Ejecuta npm.cmd run falco:auth:status o abre Authentication & permissions en Studio para revisar método, almacenamiento y permisos de lectura.
5. Manage Workers → Load Worker → revisa el estado remoto antes de modificar Workers existentes.
6. Embedded sigue siendo el modo por defecto. KV se habilita desde Manage Workers si necesitas publicar conocimiento por separado.

IMPORTANTE: el keyring de Wrangler protege OAuth, no variables CLOUDFLARE_API_TOKEN. Las comprobaciones de escritura no se ejecutan durante el diagnóstico para evitar mutaciones.

Consulta RELEASE_NOTES_v1.6.3.md para los cambios de esta versión.


## Verificación de despliegue v1.6.3

- Health y CORS se comprueban automáticamente.
- Las pruebas de chat con Gemini/OpenAI requieren marcar explícitamente la autorización de una solicitud en vivo.
- La prueba opcional de Client Actions requiere Gemini/OpenAI, una acción configurada y un mensaje de prueba. Verifica la propuesta JSON; nunca ejecuta el handler de la web.
- La prueba de Client Action usa una sola solicitud y también valida el chat.
- Los estados distinguen `pass`, `failed`, `skipped`, `not_configured`, `not_authorized` y `unsupported_provider`.
- Consulta `RELEASE_NOTES_v1.6.3.md` y `UPGRADE_v1.6.3.md` para detalles. Suite local: 129/129 pruebas.
